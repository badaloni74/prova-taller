Crea un dashboard interactivo, detallado y visualmente profesional para el proyecto “app-taller”, utilizando como fuente los documentos almacenados en la carpeta de SharePoint indicada por el usuario.

El dashboard debe estar completamente en CASTELLANO.

OBJETIVO
Crear un dashboard de trazabilidad, calidad, riesgos y estado del proyecto que permita a usuarios de negocio, analistas, QA y responsables técnicos entender rápidamente:

1. Estado global del proyecto.
2. Cobertura de requisitos.
3. Estado de los casos de prueba.
4. Defectos confirmados.
5. Preguntas abiertas y decisiones pendientes.
6. Riesgos relevantes.
7. Evolutivos en curso o pendientes.
8. Mejoras técnicas aceptadas o propuestas.
9. Requisitos más problemáticos.
10. Documentos clave y enlaces rápidos.

REGLA IMPORTANTE SOBRE DATOS
No inventes datos.

Si un dato no existe o no puede calcularse, muéstralo como:
- “No disponible”
- “Pendiente de calcular”
- “No evaluado”

No uses valores fijos si pueden calcularse desde los documentos.

El dashboard debe actualizarse con los datos actuales de los documentos de SharePoint cada vez que se regenere o actualice.

IDIOMA Y TONO
Todo el contenido visible debe estar en castellano.

Usa lenguaje claro, sencillo y útil para negocio y equipos técnicos.

Evita términos demasiado técnicos si no son necesarios. Si se usan, acompáñalos de una explicación breve.

ESTILO VISUAL
Diseña un dashboard moderno, oscuro, elegante y profesional.

Estilo recomendado:
- Fondo oscuro azul/gris.
- Tarjetas con bordes suaves.
- Colores de estado:
  - Verde: correcto o sin bloqueo.
  - Amarillo/ámbar: riesgo moderado o pendiente.
  - Rojo: crítico o acción urgente.
  - Azul: información o navegación.
- Iconografía simple y consistente.
- Tablas claras.
- Gráficos legibles.
- Evitar exceso de gráficos tipo donut.

Mantén una barra lateral izquierda con navegación.

G. Anomalías bloqueantes
- Según DOC-07, 0 anomalías bloqueantes.

H. Estado global del proyecto
No mostrar automáticamente “ON TRACK” solo porque la cobertura sea 100%.

Calcular un estado global con esta lógica:

- GREEN / En seguimiento correcto:
  - 0 defectos críticos
  - 0 anomalías bloqueantes
  - pocas preguntas abiertas
  - sin riesgos críticos abiertos

- AMBER / Requiere atención:
  - existe cobertura funcional completa, pero hay defectos críticos, preguntas abiertas, hallazgos A-05 o evolutivos pendientes

- RED / Bloqueado:
  - existen anomalías bloqueantes
  - defectos críticos sin tratamiento
  - roturas de trazabilidad
  - imposibilidad de avanzar a la siguiente fase

Para el estado actual, si se detectan 4 defectos confirmados, 2 críticos, preguntas abiertas y hallazgos A-05 abiertos, mostrar “AMBER / Requiere atención”.

REGLAS DE COHERENCIA
Antes de generar el dashboard, validar:

1. Que los totales de DOC-07 y DOC-07-MATRIZ.csv coinciden.
2. Que todos los requisitos del CSV tienen diagnóstico válido.
3. Que la suma de casos asociados coincide con 110.
4. Que no se confunde cobertura funcional con ejecución real.
5. Que no se interpreta “Correcto” como “sin defectos”.
6. Que los bugs de DOC-24 se representan como calidad/riesgo, no como GAP PLAN.
7. Que las preguntas abiertas se calculan desde el estado real de los documentos.
8. Que el estado global no sea GREEN si hay defectos críticos abiertos o riesgos altos.
9. Que si hay documentos ausentes, se indique claramente.

Si no es posible actualización automática en el entorno actual, deja preparada la estructura para regenerarlo fácilmente desde los documentos actualizados.
